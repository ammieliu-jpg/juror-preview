# 介接規格：不用知道司法院內部系統，也接得上

> 初篩模組只需要每位候選人的四個欄位。官方系統只要能匯出回覆，就能用；不必修改官方系統，也不必知道它內部怎麼做。

調查表要問什麼，是國民法官法第 13～16 條規定的，所以欄位是法律決定的，不是哪一套電腦系統決定的。
原型裡的 Google 表單與試算表，只是用來示範完整流程的收件系統（見 [ARCHITECTURE.md](ARCHITECTURE.md) 第 8 節「導入路徑」）。

---

## 1. 輸入：每位候選人一筆

| 欄位 | 鍵 | 說明 | 範例 |
|---|---|---|---|
| 候選人編號 | `id` | 通知書上的編號 | `C201` |
| 回覆 | `reply` | 到場／申請免除（也接受「拒絕被選任」）／尚未決定 | `申請拒絕被選任` |
| 勾選的事由 | `reasons` | 調查表勾選的項目，多個用逗號分隔 | `年滿 70 歲以上` |
| 具體情況說明 | `note` | 民眾自己寫的文字 | `我今年 75 歲。（附身分證影本）` |
| 時間（選填） | `ts` | 回覆時間。同一人送出多次，以最後一次為準 | `2026/11/03 09:12` |

```json
{ "id": "C201", "reply": "申請拒絕被選任", "reasons": "年滿 70 歲以上", "note": "我今年 75 歲。（附身分證影本）", "ts": "2026/11/03 09:12" }
```

## 2. 輸出：每筆申請免除一個初篩結果

```json
{
  "對應事由": "年滿七十歲以上",
  "類型": "得拒絕",
  "AI建議": "可能符合",
  "需人工確認": "否",
  "理由": "自述 75 歲，≥ 70",
  "書記官待辦": "核對身分證明後送法官",
  "依據": "國民法官法第16條",
  "src": "rule"
}
```

| 欄位 | 允許值 |
|---|---|
| `類型` | `不得擔任`／`得拒絕`／`無` |
| `AI建議` | `可能符合`／`資料不足`／`看起來不符合`（AI 沒跑時是 `待 AI 判斷`） |
| `需人工確認` | `是`／`否` |
| `src` | `rule`（規則判）／`ai`（模型判）／`pending`（沒有判，請人工審閱） |

- `書記官待辦` 不會出現「可直接送法官」。最好的情況是「核對○○後送法官」：附件只是民眾在說明裡寫的字，要有人看到實際文件。
- 結果只是初步整理，准不准由法官決定。

## 3. 三種接法（由簡單到完整）

### A. 匯入表格檔：不用改官方系統（建議先從這個開始）

1. 從官方系統匯出回覆，存成 CSV（UTF-8 或 Big5 都可以，Tab 分隔也行）。
2. 打開法院端儀表板 `court.html`，按「匯入表格檔（CSV）」選這個檔案。
3. 規則判得了的立刻有結果；判不了的標「請人工審閱」。

**資料只在這台電腦處理：不上傳、不送 AI**（就算設定裡填了 Gemini 金鑰也一樣）。瀏覽器測試會確認匯入時沒有任何往外送的請求。

欄位用標題文字找，順序不同、名稱略有不同也讀得到：

| 欄位 | 標題含有 |
|---|---|
| 候選人編號 | `候選人編號` 或 `編號` |
| 勾選的事由 | `事由` |
| 具體情況說明 | `說明` |
| 時間 | `時間` 或 `日期` |
| 回覆 | `回覆` 或 `意願` |

標題認不出編號或回覆時，照 A–E 欄的順序讀（時間、編號、回覆、事由、說明）。
範例檔：[`tests/fixtures/import-utf8.csv`](../tests/fixtures/import-utf8.csv)（同內容的 Big5 版：`import-big5.csv`）。

### B. 把初篩模組放進法院的系統

`lib/screening.js` 是純函式：不碰網頁、不碰 Google 服務，輸入一筆、輸出一筆。

```js
const S = require('./lib/screening.js');

async function screen(app, askCourtModel) {
  if (S.normalizeReply(app.reply) !== '申請免除') return null;
  let out = S.ruleClassify(app);                                   // 規則判得了：不用 AI
  if (!out) {
    const text = await askCourtModel(S.buildPrompt(app));          // 判不了：問法院自建的模型
    out = S.checkAI(S.parseJson(text), app);                       // 每個欄位比對允許值
  }
  return S.finalize(out, app);                                     // 欄位一致、附件種類核對
}
```

法院的系統不是 JavaScript：照 [`tests/fixtures/exemptions.json`](../tests/fixtures/exemptions.json) 的 44 筆標註案例改寫，跑同一份案例，確認每一筆結果都一樣。

### C. 法院內網服務

把 B 包成內網服務，給收件系統呼叫；模型接法院自建的模型（例如 TAIDE）。
原型的 `apps-script/main.gs` 已經示範「只有一個地方呼叫模型」（`callLLM_()`），換模型只改那裡。

## 4. 導入前要和司法院確認的事

我們沒有官方系統的內部資料，下列事項要先確認，不用猜：

- [ ] 官方線上調查表能不能匯出？格式（CSV、Excel）與欄位名稱
- [ ] 「回覆」與「事由」選項的實際文字
- [ ] 附件怎麼收（線上上傳、郵寄），書記官在哪裡看到實際文件
- [ ] 候選人編號的格式（用來檢查假資料，目前原型假設是一個英文字母加 3～6 位數字）
- [ ] 能不能提供去識別化的歷史申請，建立不拿來調規則的獨立測試集

格式和這份規格不同時，通常只要改「標題含有」的對照（`lib/screening.js` 的 `COLUMNS`）。
